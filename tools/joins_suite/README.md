# Joins suite and differential

Two off-tier checks for zpq's joins. No gate runs them. Both need Python 3 (standard library only) and the DuckDB 2.0.0 CLI. The differential always needs DuckDB, and the suite needs it only for `--record` and `--engine duckdb`.

## `suite.py`: 104 analyst queries on real public data

`cases.json` holds 104 join queries, written the way an analyst writes them for DuckDB, and 24 workaround rewrites (`--set workaround`) of queries zpq refuses. Each case carries DuckDB 2.0.0's answer.

The queries read four public datasets stored in the S3 bucket `zpq-public-data`:

- **TPC-DS SF10**, generated by DuckDB's `dsdgen`;
- **NYC TLC trip records**, January to June 2024 as published, with the taxi zones and NOAA Central Park weather;
- **Lahman Baseball Databank**;
- **Chinook**.

The bucket's `README.md` gives each dataset's source, license and Parquet writer.

```sh
export S3_ACCESS_KEY_ID=... S3_SECRET_ACCESS_KEY=... S3_ENDPOINT_URL=http://host:9000 S3_REGION=us-east-1
export ZPQ_TEST_PARQUET_DIR=/fast/disk/zpq-test        # the data lands in $ZPQ_TEST_PARQUET_DIR/zpq-public-data
just joins-suite                                       # build and run: local, then S3
python3 tools/joins_suite/suite.py --zpq zig-out/bin/zpq [--local | --s3] [-v] [--json out.json]
```

It prints one score line, with one part for local files and one for S3:

```
joins-suite analyst (104) zpq 0.5.2 (c16bb54764b3): local 28 correct, 73 refused (44 named, 29 unnamed), 3 wrong, 0 crash | s3 0 correct, 104 refused (97 named, 7 unnamed), 0 wrong, 0 crash
```

**Classes:**

| class | meaning |
|---|---|
| **correct** | Equals DuckDB's answer. Rows are compared in order when the outer query has ORDER BY, and as multisets otherwise. Floats must agree to 1e-9 relative. zpq's DECIMAL `avg` is accepted at its own fixed scale (6 places, or the input's for DECIMAL(38,s)) when it is DuckDB's DOUBLE rounded there. |
| **refused, named** | zpq exits 1 or 2 with a message that names the missing feature. |
| **refused, unnamed** | zpq exits 1 or 2, but the message names no feature: a bare error name such as `FileNotFound` or `UnsupportedFromClause`, "unknown column referenced in expression", "\`\` is an expression", or "column is ambiguous". The patterns are `common.UNNAMED`. |
| **wrong** | zpq answers, and the answer differs from DuckDB's. This includes the same rows in another order under ORDER BY. |
| **crash** | A signal, an exit code other than 0, 1 or 2, a panic or `error.X` in stderr, or a timeout. |

The exit status is 1 when any case is wrong or crashes. With `--fail-unnamed`, an unnamed refusal also gives exit 1.

**Data:**
- Local runs download whatever tables are missing, and only the tables the chosen cases read. That's about 5 GB for all of them. Use `--data DIR` or `ZPQ_JOINS_DATA` to put the copy elsewhere, and `--fetch-only` to download without running anything.
- The S3 pass reads `s3://zpq-public-data/...` directly. It runs only when credentials are set.
- **Credentials come from the environment only:** `S3_*` first, then `AWS_*`. They are never printed, written to disk or passed in argv. DuckDB gets its secret on stdin.

**Other flags:**

| flag | what it does |
|---|---|
| `--ids ds01,tl08` | runs the named cases only |
| `--tlc-single` | replaces the six-month TLC globs with the January file, to see past a glob refusal. Those cases carry a second answer for this mode. |
| `--engine duckdb [--s3]` | scores DuckDB itself, as a check of the harness and the data. It should give 104 correct in both places. |
| `--reps N` | sets the `ms` in `--json` to the median of N fresh-process runs |
| `--record` | re-records every answer with DuckDB on the local copy |

## `differential.py`: randomized zpq vs DuckDB

Each seed builds its own small tables with DuckDB, deterministically: one thread and `setseed`, with row-group sizes and key offsets chosen at random. It then generates `--queries` join queries over them and runs each one through DuckDB and through any `--zpq` binary. Outcomes use the suite's classes. A refusal is never a failure; a wrong answer or a crash is.

```sh
python3 tools/joins_suite/differential.py --zpq zig-out/bin/zpq --seeds 1-12 --queries 40 [--shapes nullpay,strkey] [--json out.json] [-v]
```

| shape | covers |
|---|---|
| inner, star, snow, left, semi, semidup, anti | integer keys (INTEGER or BIGINT, offsets up to ±2^31 and 2^40), NULL FKs at 0–90%, holes in the dimension, residuals across sides |
| derived | HAVING on one derived column, ORDER BY another, LIMIT and OFFSET over a join's GROUP BY |
| nullpay | build columns (INTEGER, VARCHAR, DECIMAL(9,2)) NULL at 0–90%: in SELECT, GROUP BY, WHERE and a residual against the probe; NULL told apart from a LEFT miss; through a snowflake |
| strkey | string keys: empty, multibyte (Cyrillic, CJK, emoji), shared prefixes (`key`, `key0`, `key00`), leading and trailing spaces, case, NFC vs NFD; inner, LEFT, IN, NOT IN, LIKE on the key |
| composite | 2 or 3 key columns of mixed types (INTEGER, VARCHAR, DATE) with NULL parts on both sides; inner, LEFT, GROUP BY, [NOT] EXISTS |
| self | a table joined to itself: parent lookups, LEFT misses, comparisons of same-named columns, two levels |
| rows | row output with duplicate rows under ORDER BY, LIMIT and OFFSET, DISTINCT, LEFT, semi |
| exists | [NOT] EXISTS with NULLs on both sides, beside the matching [NOT] IN |
| globfk | multi-file probe grouped by its FK or the build key, including HAVING, ordering and pagination |

Tables go under `--dir`, or `$ZPQ_TEST_PARQUET_DIR/joins-differential` when that isn't given. They are removed afterwards unless you pass `--keep`. The last line is the score, and above it is a table of classes by shape.
